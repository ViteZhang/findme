# 研发交接说明：AI 自我探索教练（V0.5）

> 版本：v1.0 ｜ 日期：2026-11-25
> 读者：研发（前端、后端、AI 应用）
> 用途：研发的第一份文档。说明其他文档怎么读、V0.5 要做哪些功能、以及其他文档里没写的技术要求。本文不重复已有内容，只给出处。

---

## 1. 一句话说明

一个响应式网页应用：AI 教练通过多轮对话，从用户讲的真实经历里收集**证据**，按固定规则计算每条**线索**的置信度，最后整理成一份每条结论都能追溯依据的个人优劣势**画像**。

V0.5 只给产品负责人自己用，但数据结构和隔离要按多用户设计，V1 会邀请 3–5 人试用。

## 4. 技术要求（其他文档没写的部分）

### 4.1 平台

| 项 | 要求 |
|---|---|
| 形态 | **响应式网页**，一套代码 |
| 断点 | < 768 移动端；768–1279 中屏；≥ 1280 桌面。设计稿宽度 390 / 1024 / 1440 |
| 浏览器 | Chrome、Edge、Safari 最近两个大版本；iOS Safari 16 及以上 |
| 设计令牌 | 直接使用设计规范里的 `--page-*` 变量；字体 Noto Sans SC 400 / 500 + JetBrains Mono |
| 动效 | 统一缓动 `cubic-bezier(.22, 1, .36, 1)`；必须支持 `prefers-reduced-motion` |

### 4.2 账号与数据隔离

- V0.5 只有一个用户，但**必须登录**（建议邮箱验证码），因为内容高度私密
- 所有数据表从第一天起带 `user_id`，查询全部按用户隔离，V1 不需要迁移
- 会话保持 30 天；导出和删除全部数据前要求重新验证

### 4.3 数据安全与隐私

| 项 | 要求 |
|---|---|
| 传输 | 全站 HTTPS |
| 存储 | 数据库加密；故事 STAR、证据原话、反馈回复建议字段级加密 |
| 模型服务 | **必须确认所用大模型服务不使用这些数据训练，并开启最短数据留存**。这是产品对用户的承诺，选型时先确认 |
| 日志与埋点 | 不记录对话原文；安全事件只记信号类别，不记原话 |
| 导出 | JSON + 可读的 Markdown |
| 删除全部数据 | 硬删除；写明备份的保留期（建议不超过 30 天），在隐私说明里告知 |
| 测评原文件 | 解析后按用户选择删除（R7） |

### 4.4 性能

| 场景 | 目标 |
|---|---|
| 教练回复 | 流式输出；首字 ≤ 2 秒，完整回复通常 ≤ 10 秒 |
| 页面首屏 | ≤ 2 秒；超过 300ms 才显示骨架，超过 8 秒换成错误页 |
| 置信度重算 | 单条线索 ≤ 100ms；删除故事的影响预览 ≤ 1 秒 |
| 画像生成 | 设计稿写约 30 秒，上限 60 秒；可以离开，后台继续 |
| 测评解析 | ≤ 30 秒 |

### 4.5 成本

请研发评估每次对话的模型调用量，记录每次会话的 token 用量。V0.5 单用户成本不是约束，但 V1 前需要一个估算。

### 4.6 提醒

响应式网页在 iOS 上只有「添加到主屏幕」后才能收到推送。**V0.5 的打卡提醒渠道待定**，见第 8 节。

## 5. 建议的系统结构

供研发参考，最终方案由研发定。

```
浏览器（响应式网页）
   │  对话流式接口 · 页面数据接口
   ▼
后端服务
   ├─ 对话编排（主智能体）
   │    1. 安全检测（每轮先跑，结果优先）
   │    2. 路由：条件类规则用代码判断（计数、状态），意图类交给模型
   │    3. 调用当前技能：技能提示词 + 允许使用的工具
   ├─ 工具层（技能只能通过它读写数据）
   ├─ 置信度引擎（纯代码，确定性）
   ├─ 文件解析（测评 PDF / 图片识别）
   └─ 数据库（按数据模型 v0.6 建表）
```

**三条硬约束**

1. **置信度只由引擎计算**：AI 只能写入证据和用户回应，不能直接设置等级或状态
2. **安全检测先于一切**：每轮用户输入先过安全检测；暂停期间工具层拒绝写入故事、线索、证据（R6）
3. **技能输出统一格式**：每个技能结束时返回技能规格〇.4 规定的结构（状态、写入了什么、小发现、建议下一步）

## 6. 接口约定（工具层）

技能通过下面这些工具读写数据。字段名以数据模型为准，这里只约定工具和关键返回。

| 工具 | 输入（要点） | 返回（要点） | 规则 |
|---|---|---|---|
| `profile.get` / `profile.update` | 档案字段 | 用户档案 | 只有目标设定和设置页写入 |
| `progress.get` / `progress.update` | 模块状态、计数、`last_session` | 对话进度 | 首页开场句和路由读取它 |
| `story.create` / `story.update` | mode、title、star、key_moment、emotion_intensity | story_id | 低谷故事情绪强度 ≥ 4 时通知安全检测 |
| `story.delete` | story_id、`preview: true/false` | preview 时返回受影响线索的等级变化 | 先 preview 再执行；执行后批量重算 |
| `clue.find_similar` | statement、dimension | 候选线索和相似度 | 新线索前必调（数据模型 9.1） |
| `clue.create` | statement、type、dimension、created_by | clue_id | 一条线索只有一种类型 |
| `evidence.add` | clue_id、direction、source_type、source_ref、excerpt、interpretation、strength | evidence_id + 重算结果 | 写入后自动重算 |
| `evidence.deactivate` | evidence_id | 重算结果 | 「这条不算」，可撤销 |
| `clue.respond` | clue_id、stance、user_statement | 重算结果 | 否认计数在这里处理 |
| `clue.merge` / `clue.split` | from、to、auto | 合并结果 | 已确认线索的合并必须带用户同意 |
| `confidence.compute` | clue_id | 见下方 | 只读，任何地方都可调用 |
| `portrait.generate` / `portrait.confirm_section` | — / section、edits | 画像版本、自检结果 | 生成时保存线索快照 |
| `safety.record` / `safety.status` | level、signal_category | 当前是否暂停、`resume_not_before` | 不传原话 |

### `confidence.compute` 返回结构

```json
{
  "clue_id": "clue_0001",
  "level": "中",
  "status": "成立中",
  "N": 2,
  "S": 1,
  "W_plus": 2.5,
  "W_minus": 0,
  "gates": {
    "evidence_count": {"value": 2, "target": 3, "met": false},
    "source_kinds":   {"value": 1, "target": 2, "met": false},
    "weighted_score": {"value": 2.5, "target": 3.0, "met": false},
    "own_experience": {"value": true, "met": true, "applies": true}
  },
  "caps": [],
  "next_needed": "还差 1 条来自测评、价值观澄清或他人反馈的证据"
}
```

- `gates` 直接驱动界面上的门槛条和刻痕空位
- `own_experience.applies` 只对优势候选为 true（规则 B5）
- `caps` 列出封顶原因，例如「缺本人经历」「反对证据较多」
- `next_needed` 是首页线索卡和线索详情「还差什么」的文案来源

## 7. AI 部分怎么交付和验收

### 7.1 交付物

技能规格写的是「AI 应该怎么做」，不是提示词。每个技能需要研发交付：

1. 技能提示词（系统提示 + 示例）
2. 允许使用的工具列表
3. 输出结构校验
4. 对应测试样例的通过记录

主智能体的人格、语气、全局规则（技能规格〇.5）写成一个所有技能共用的基础提示词。

### 7.2 验收方式

- 把测试对话样例的每个样例变成一个脚本化对话：用户消息固定，检查 AI 的回复和数据写入
- 「数据变化」部分用代码断言；「检查点」里的语气类条目由产品负责人人工评审
- 每次改提示词都跑一遍全部样例
- V0.5 适用的样例见测试样例 v0.5 的验收汇总表

### 7.3 置信度引擎测试向量（必须全部通过）

| 来源 | 输入 | 期望 |
|---|---|---|
| 数据模型 8.6 | 经历强 + 他人反馈中 ×2 + 测评中（同一故事的第二条去重） | N=4，S=3，W+=4.0，高 |
| 测试样例升级路线 · 样例 3 | 经历强 + 经历中 | N=2，S=1，W+=2.5，中 |
| 测试样例升级路线 · 样例 7 | 再加能量弱 | N=3，S=2，W+=2.9，中（加权分差 0.1） |
| 测试样例 V0.5 路线 | 经历强 + 经历中 + 测评中 | N=3，S=2，W+=3.0，高 |
| 测试样例 9 | 优势候选：他人反馈中 ×3 + 测评中，无本人经历 | 数值达标，封顶为中，`caps` 含「缺本人经历」 |
| 设计第 2 批删除预览 | 删除 story_0001 | 梳理结构 高→中（3.0→1.5）；画图画表 中→中；牵头活动 中→已归档 |
| 数据模型 8.5 | 用户否认 1 次 / 2 次 | 降一级 / 归档 |
| 测试样例 E7 | 两难题只选不说理由 | 价值观证据强度为弱 |
| 测试样例 E9 | 中风险暂停期间调用 `evidence.add` | 拒绝写入 |
