## 一、交付目标与评审范围

第一版交付一个需要登录的中文响应式网页，供产品负责人自己使用。用户从真实经历出发，看见教练如何从原话提炼线索，能纠正或否认，再把经过多种来源印证的发现整理成可追溯、可逐节修改的画像。第一条端到端验收路径选「讲两个故事 → 补一份大五测评 → 同一条线索升高 → 点回三处依据」。这条路径成立后，再用满足整份画像门槛的数据验收生成、确认和导出。

本次评审对象是范围、业务口径、技术提案、顺序和验收标准。确认后从 M0 开始；服务采购、域名和面向外部用户开放均需有具体决定。

## 三、技术与数据方案（拟采用）

- **应用结构。** 建议一个 TypeScript 仓库，React 响应式界面、Node 服务端、Supabase PostgreSQL 和私有 Storage，前端与 API 由 Vercel 部署。把页面/API、领域规则、教练编排、后台任务划为独立模块。画像和解析以持久任务表记录进度，后台执行，刷新后按任务 ID 继续。队列与进度持久化到 PostgreSQL；执行器可重入，重试按任务标识去重。上传使用私有桶与限时授权。
- **账户与存储。** 业务表从第一版带 user_id；归属从登录会话取得，跨表引用校验同一用户。实现验证码过期、限频、30 天会话和导出／清空前重新验证。核心表覆盖档案、进度、故事、线索、证据、回应、关系与合并记录、价值观、测评、打卡、反馈、画像版本、安全事件、变更及调参日志。另存会话步骤、任务和同意版本，为续聊和审计提供依据。
- **写入链路。** 页面和技能都通过领域服务操作。一次用户动作携带唯一请求标识；证据写入、线索重算、进度更新和变更记录在同一事务中完成。网络重发、模型工具重复调用、双击确认只生效一次。删除预览与提交复用计算逻辑；预览后若数据变化，重新展示影响。合并保留全部来源和撤销依据。
- **AI 边界。** 每轮服务端先判安全，再按进度与意图路由。每个技能交付基础人格提示、技能提示与示例、可用工具、结构化输出校验和回归记录。模型提议说法、出处、解释与强度；服务端验证来源、归属和写权限，独立计算等级。模型超时或返回无效结构时可重试，未完成的结构化结果不落入证据库。
- **隐私与运维。** HTTPS、加密磁盘与备份，故事、证据摘录、反馈等敏感字段加密，密钥与存储分开管理。日志只记请求标识、耗时、错误类型、模型版本和 token 量。测评原件私有保存，按用户选择清除并记住偏好；全量删除涵盖附件、派生文件、历史画像和排队任务。备份恢复演练要验证已申请删除的数据不会重新对用户可见。
- **前端。** 原样复用规范的 --page-*、字体、间距与动效，落实减弱动效、键盘操作及焦点恢复。390／1024／1440 三宽度逐批核对，补测 767／768、1279／1280 的切换。中屏图标栏与发现抽屉、手机底部导航与抽屉分别验收。删数据用深色危险按钮，警示红只用于高风险安全提示。

## 五、业务规则如何验证

**引擎只有一份。** 对每条线索取有效证据，按独立性键去重取最强；同一故事或同一种测评重复出现只占一笔。用户自述可贡献权重，不计 N 和 S。分别计算支持数 N、来源种类 S、加权支持 W+ 和反对 W−。前端使用引擎返回的等级、封顶原因和下一步，删故事、画像和首页共用结果。

| 固定输入或动作 | 核验点 |
|---|---|
| 两个独立故事，强＋中；随后补大五测评中 | 前一步 N=2、S=1、W+=2.5，为中；后一步 N=3、S=2、W+=3.0，无反证时为高 |
| 同一故事出现两次；另加两位反馈人和一份测评 | 最高强度计入一次，按数据模型 §8.6 得 N=4、S=3、W+=4.0。反馈及能量的计算使用固定夹具，首版收集界面不调用证据写入 |
| 能量弱使 W+=2.9；优势候选仅有反馈与测评；反对权重恰达 W+ 的 30% | 分别验证加权不足、缺本人经历、反证封顶。优势详情额外显示第 4 条门槛；反证达到支持权重时按数据模型降至线索并供探讨 |
| 否认一次／两次；撤销合并；停用一条证据；删除故事 | 分别降一级／归档，撤销后恢复来源，停用和删除引发重算。档案和用户看到的变更记录可解释每次变化 |
| 中／高风险到达时，有旧对话、后台任务或断线重试在途 | 安全检查优先；暂停期间拒绝写故事、线索和证据；中风险暂停探索，高风险中断全部技能并持续展示求助资源。安全事件只记类别。恢复需用户主动、下一轮无风险、教练确认；高风险距事件至少 24 小时，再选方向 |
| 首次定稿、第二版、随后删除来源 | 八节依次为核心优势（附习得技能）、别人眼中的你、短板、价值观 Top 5、能量模式、最佳状态说明书、待观察、版本变化。证据不足时如实留空；打卡观察标「不计入」；标题含 R5 提示。既有版本按 C 项决定处理删除 |

**AI 回归。** 固定用户输入，对样例 1～6、7 的打卡段、9、10、12 和 E1～E9 检查工具调用、数据前后差异、跳过及恢复。每次提示词变更重跑适用用例；负责人抽看追问是否自然、是否替用户做决定、是否使用标签或夸大证据。例 8、11 及例 7 周报部分留给后续版本。首版也不开放行为实验、反方审核子智能体、时间衰减、多人试用及教练模式。

**页面与非功能验收。** 用框架 F1～F10 穿行首访、讲故事、补测评、价值观、画像、打卡、安全中断、纠错、删故事、回访。核对六批画板中的空态、加载、离线、出错、重试及中断恢复。覆盖 Chrome、Edge、Safari 最近两个大版本和 iOS Safari 16 起；报告记录实际设备、浏览器、网络、模型、样本数和延迟分布。目标为首屏及教练首字 ≤2 秒，回复通常 ≤10 秒，单线索重算 ≤100 毫秒，删除预览 ≤1 秒，测评解析 ≤30 秒，画像约 30 秒、上限 60 秒。首屏超过 300 毫秒再出骨架，超过 8 秒给错误与重试入口。

## 六、评审与交接方式

每一阶段提供一条负责人可亲自走的验收路径、对应测试数据、通过／失败记录和本阶段尚待决定的问题。涉及证据计分、删除语义、安全暂停或画像门槛的变更，同时更新规则、夹具和页面验收条件。A～D 的确认状态见第二节。M0 继续验证真实服务的接入条件；E、F 按所列节点决定。
