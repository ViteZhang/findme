## 〇、通用约定（所有技能共用）

### 1. 共享数据对象

| 对象 | 关键字段 | 谁写入 | 谁读取 |
|---|---|---|---|
| **用户档案** | 昵称、探索目标、当前困惑、所处阶段、偏好的沟通风格 | 目标设定 | 全部技能 |
| **故事** | ID、类型（高光/低谷/日常）、STAR 内容、情绪强度（1–5）、日期 | 经历挖掘 | 画像生成、反方审核 |
| **线索** | ID、描述、类型、维度、状态、置信度、用户回应、否认次数 | 多个技能 | 画像生成、行为实验 |
| **证据** | ID、指向的线索、支持/反对、来源类型、独立性键、原话摘录、强度 | 多个技能 | 画像生成、反方审核 |
| **画像** | 版本号、优势、短板、价值观、能量模式、最佳状态说明书、生成日期 | 画像生成 | 用户、行为实验 |
| **对话进度** | 每个模块的状态（未开始/进行中/完成）、上次停在哪里 | 主智能体 | 主智能体 |

> 完整字段、状态机和计算细节见《数据模型设计：线索/证据库》。两份文档有出入时，以数据模型文档为准。

### 2. 线索类型与维度

- **类型**：优势候选 / 习得技能 / 短板候选 / 价值观 / 能量来源 / 能量消耗 / 行为模式 / 盲点 / 不一致
  - **习得技能**：做得好，但做完消耗大（能力类证据支持、能量类证据反对），画像中与核心优势分开标注
  - **不一致**："说的"和"做的"不一致，只在对话中探讨，不进画像
  - **一条线索只有一种类型**：一段材料同时指向两种类型时（如既是价值观又是能量消耗），拆成两条线索并互相标记"相关"，分别计算置信度；同一个故事可以给两条线索各提供 1 条证据
- **维度**：对应"5+1"框架（性格、能力、价值观、能量、关系、盲点）

### 3. 置信度规则

**3.1 证据来源与权重**

| 来源 | 产生技能 | 基础权重 | 独立性（多少算 1 条） |
|---|---|---|---|
| 经历 | 经历挖掘 | 1.0 | 每个故事算 1 条 |
| 价值观 | 价值观澄清 | 0.8 | 每次价值观澄清算 1 条 |
| 能量 | 能量分析 | 0.8 | 每份周报算 1 条（满 14 天数据才能产生"中"及以上强度） |
| 他人反馈 | 他人反馈 | 1.0 | **每位反馈人各算 1 条** |
| 测评 | 测评解读 | 0.5 | 同一种测评只算 1 条；**MBTI 不计入证据** |
| 实验 | 行为实验 | 1.2 | 每次实验算 1 条 |
| 用户自述 | 任意技能 | 0.3 | 只算 1 条，且不计入 N 和 S，不能单独让线索升级（用户主动新建的线索也从这里起步） |

**证据强度**（由产生证据的技能判断）：强 = 1.5（有具体行为、结果和明确的情绪/能量信号），中 = 1.0（有具体事例但不完整），弱 = 0.5（间接关联或只有概括）。

**3.2 计算口径**

- **N**：去重后的有效支持证据数（不含用户自述）
- **S**：支持证据涉及的来源种类数（不含用户自述）
- **W+ / W−**：支持 / 反对证据的加权分 =Σ（基础权重 × 强度系数）

**3.3 等级判定**

| 等级 | 条件（同时满足） | 线索状态 | 在画像里怎么呈现 |
|---|---|---|---|
| **线索** | 不满足"中" | 待观察 | 不进正文，只进"待观察"清单 |
| **中** | （N ≥ 2 且 W+ ≥ 1.5）或（N ≥ 1 且用户认同且该证据强度 ≥ 中） | 成立中 | 写成"可能是……" |
| **高** | N ≥ 3，S ≥ 2，W+ ≥ 3.0，且 W− < W+ × 0.3 | 已成立 | 写成核心结论，措辞"明显" |
| **已验证** | 达到"高" + 至少 1 次行为实验结论为"支持" | 已验证 | 加"✅已验证"标记 |

- **优势类线索的额外门槛**：`优势候选` 要到"高"，支持证据中至少要有 **1 条本人经历证据**（经历或实验）。没有的话封顶为"中"，标记"待补例子"，画像中放进"别人眼中的你"一节。原因：别人只能看到"做得好"，"做完有能量、愿意持续做"只有用户自己能回答
- **他人未提及不算反证**：自评有、反馈里没人提到的特质，不影响置信度，只标记"他人未提及"。只有反馈人明确说出相反的情况，才算反对证据

**3.4 降级与归档**

| 情况 | 处理 |
|---|---|
| 用户否认（第 1 次） | 降一级，并追问更准确的说法 |
| 用户否认（第 2 次） | 归档（不进画像，保留记录，用户可要求恢复） |
| W− ≥ W+ × 0.3 | 最高只能到"中"，画像中写"可能是……，但也有相反的情况" |
| W− ≥ W+ | 降为"线索"，并创建"不一致"或替代线索供探讨 |
| 实验结论为"推翻" | 产生一条强反对证据，重新计算 |

> 置信度由证据实时计算，状态不能手动直接修改；每次变更都写入变更日志。

**3.5 时间与调参**

- **V0.5 证据不随时间衰减**，只在画像措辞中优先使用较新的证据；V1 改为按维度衰减（性格、价值观不衰减，其他维度旧证据降权）
- 用户觉得某条结论"不像我"或"早该成立了"时，记入调参日志，供 V1 调整阈值

### 3.6 合并与用户新建线索（全局规则）

- **合并**：未确认的线索由 AI 自动合并，标记为"待过目"；已确认的线索合并前必须先问用户；画像生成前统一列出所有自动合并给用户过目，不同意即撤销
- **用户新建线索**：用户直接说"我觉得我很 XX"时，任何技能都可以登记为新线索（附一条自述证据），并**当场追问一个具体例子**；用户讲了就转入经历挖掘，想不起来就标记"待补例子"，不强求

### 4. 技能输出的统一格式

每个技能结束时都向主智能体返回：

```
状态：完成 / 中断 / 需要转交
写入：新增或更新了哪些故事、线索
给用户的小发现：一句话
建议下一步：推荐进入哪个技能
```

### 5. 全局对话规则

- 一次只问一个问题
- 每轮回复 150 字以内（生成报告时除外）
- 先复述确认，再提炼线索
- 不贴人格标签，不做诊断
- 安全守护始终在后台运行，优先级最高

## 0️⃣ 主智能体：成长教练（编排规则）

**职责**：维持统一人格，判断用户当前该进哪个技能，不亲自做深度分析。

### 路由表

| 情况 | 调用 |
|---|---|
| 新用户，或用户档案为空 | 目标设定 |
| 用户说"想聊聊某件事"，或故事少于 5 个 | 经历挖掘 |
| 用户直接给出自我判断（"我觉得我很 XX"） | 登记线索 + 追问例子，讲出例子后转经历挖掘 |
| 有标记"待补例子"的线索，且当前对话有空档 | 经历挖掘（围绕该线索请用户讲例子） |
| 故事 ≥ 3 个，但价值观模块没开始 | 价值观澄清 |
| 用户上传测评报告 | 测评解读 |
| 用户说"想听听别人怎么看" | 他人反馈 |
| 高置信度线索 ≥ 3 条，或用户要求 | 画像生成 |
| 已经有画像，用户想"试一试"或"验证一下" | 行为实验 |
| 每周日，或日志打卡 ≥ 5 天 | 能量分析（后台，V1 启用；V0.5 只记录打卡） |
| 出现风险信号 | 安全守护（中断其他所有技能） |

### 回访开场

读取对话进度，用一句话衔接上次内容，例如：

> "上次我们聊到你组织活动的经历，还发现了'结构化'这条线索。今天想接着挖一个故事，还是换个方向？"

## 1️⃣ 目标设定

| 项 | 内容 |
|---|---|
| **定位** | 破冰，了解用户为什么来，设定探索期望 |
| **触发** | 第一次使用；用户说"重新开始"或"我的目标变了" |
| **输入** | 无（或已有用户档案） |
| **预计时长** | 5–10 分钟 |

### 流程

1. 自我介绍，说明这是怎样的过程：大约几周，会挖经历、收集证据，最后生成画像
2. 问来意："是什么让你想更了解自己？"
3. 追问现在的处境：最近有没有正在纠结的选择或困惑
4. 问期待的结果："聊完之后，你最希望得到什么？"（选项：职业方向 / 理解自己的情绪和行为 / 改善人际关系 / 单纯好奇）
5. 问沟通偏好：直接一点还是温和一点，要举例子还是只要结论
6. 说明隐私规则，以及随时可以删除数据
7. 复述总结，请用户确认

### 规则

- 这一步不分析，只倾听和记录
- 用户困惑很具体时（如"要不要辞职"），说明这里先了解自己，不直接替他做决定

### 输出与完成

- **输出**：用户档案（目标、困惑、阶段、偏好）
- **完成标准**：用户确认了目标总结
- **建议下一步**：经历挖掘（高光模式），从积极经历开始门槛最低

## 2️⃣ 经历挖掘

| 项 | 内容 |
|---|---|
| **定位** | 产品的主线技能，从真实故事里提炼线索 |
| **模式** | 高光模式 / 低谷模式 / 日常模式（最近一周的小事） |
| **触发** | 主智能体调用，或用户主动说"我想聊一件事" |
| **输入** | 模式、用户档案、已有故事（避免重复）、已有线索 |
| **预计时长** | 每个故事 10–15 分钟 |

### 流程

1. **引出故事**（按模式选问法）
   - 高光："有没有哪件事，你做完觉得'这才是我'？"
   - 低谷："有没有哪段经历让你特别挫败，或者特别想逃开？"
   - 日常："这周有没有哪个瞬间，让你觉得特别顺，或者特别别扭？"
2. **STAR 追问**（最多 4 轮，每轮一个问题）：情境 → 你的任务 → 你具体做了什么 → 结果和感受
3. **关键追问**（按模式二选一）
   - 高光："哪个环节你最投入，时间过得最快？"
   - 低谷："最难受的是哪个点？是事情本身，还是别的什么？"
4. **提炼**：给出 1–2 条线索并附依据（一条材料指向两种类型时拆成两条），例如："我注意到一个可能的线索：**擅长把复杂的事结构化**。依据是你说最投入前期梳理。你觉得准吗？"
5. **处理用户回应**
   - 认同：记为"用户确认"
   - 部分认同：请用户修正说法
   - 否认：按降级规则处理（第 1 次降一级，第 2 次归档），并问"那你觉得更准确的说法是什么？"
6. **合并**：在同一维度内检查是否有相似线索
   - 高度相似：不新建，作为证据追加，并告诉用户"这已经是第 N 次出现了"
   - 一个是另一个的具体表现：新建，并标记"包含"关系
   - 方向相反：作为反对证据追加，或标记"矛盾"关系
   - **未确认的线索**：自动合并，不打断对话，标记为"待过目"
   - **已被用户确认过的线索**：合并前必须先向用户复述并征得同意
7. **打强度**：按证据强度标准（强/中/弱）给本条证据打分；同一个故事拆出的多条证据，只按最强的一条计入

### 规则

- 低谷模式开头先告诉用户可以随时跳过，语气更温和
- 用户只说概括（如"我挺擅长沟通的"）时，先登记为线索 + 自述证据，再请他讲一件具体的事
- 连续两轮回答少于 15 个字，就换个问法；仍不行就建议换个故事或先休息
- 情绪强度 ≥ 4 的低谷故事，同时通知安全守护关注

### 输出与完成

- **输出**：1 个故事 + 1–2 条线索（新增或合并）
- **完成标准**：故事 STAR 要素齐全，且至少有 1 条线索得到用户回应
- **建议下一步**：
  - 高光故事 < 3 个：继续高光模式
  - 高光故事 ≥ 3 个、低谷故事 < 2 个：进入低谷模式
  - 都满足：进入价值观澄清

## 3️⃣ 价值观澄清

| 项 | 内容 |
|---|---|
| **定位** | 找出用户真正看重的东西，而不是"应该"看重的东西 |
| **触发** | 已有 ≥ 3 个故事；用户面临选择 |
| **输入** | 已有故事和线索、价值观词库（约 30 个，如自由、成就、安全、认可、成长、关系、意义、影响力、稳定、创造……） |
| **预计时长** | 15–20 分钟 |

### 流程

1. **初选**：从词库中挑出 10 个最有共鸣的
2. **两两取舍**：根据选择出两难题，如"一份钱多但不自由的工作，和一份自由但收入不稳的工作，你选哪个？为什么？"，进行 5–7 轮
3. **对照故事**：用已讲过的故事验证，如"你说'自由'排第一，你讲的那次低谷经历，是不是也和被管得太细有关？"
4. **找"说的"和"做的"不一致之处**：如用户说看重"成长"，但几个高光故事都和"被认可"有关，温和地提出来作为探讨问题
5. **排出 Top 5**：每个价值观请用户用一句话说明"对我来说它意味着什么"

### 规则

- 不评判价值观的好坏
- 用户说"都重要"时，用更极端的取舍逼出排序；**最多追问 2 次**，之后允许跳过这道两难题，不催促（R3）
- **两难题的理由算作证据**：每道题选完后请用户用一句话说为什么，理由原话作为"价值观"来源的证据；只选不说理由时，证据强度记为"弱"（R1）
- 不一致之处只作为探讨问题，不能当成"你在骗自己"

### 输出与完成

- **输出**：价值观 Top 5（附用户自己的定义）+ 价值观类线索 +（如有）不一致线索
- **完成标准**：用户确认 Top 5 排序

## 4️⃣ 能量分析

| 项 | 内容 |
|---|---|
| **定位** | 通过持续的小记录，找出什么让人充电、什么让人耗竭 |
| **V0.5 范围** | ⏸ 只做每日打卡并存储，不生成周报、不产生证据；完整功能在 V1 上线 |
| **子功能** | 每日打卡（前台，1 分钟）+ 每周分析（后台） |
| **触发** | 打卡：每天定时提醒；分析：每周日或打卡满 5 天 |
| **输入** | 打卡记录、已有线索 |

### 每日打卡流程（固定 3 问）

1. 今天整体能量打几分？（1–10）
2. 今天最让你充电的一件事是什么？
3. 今天最消耗你的一件事是什么？
4. （可选）还有什么想补充的吗？

### 每周分析流程

1. **归类**：活动类型（独处/协作/社交/执行/创造）、和谁在一起、在什么环境
2. **找规律**：哪类活动反复出现在"充电"栏、哪类反复出现在"消耗"栏，能量分数与哪些因素相关
3. **对照线索**：如"结构化"线索是否对应"做规划时能量高"
4. **生成周报**：3 个规律 + 1 个建议（如"下周可以把需要深度思考的任务排在上午"）
5. **反馈确认**：下次对话开头告诉用户，请他确认

### 规则

- 打卡必须控制在 1 分钟内，不能加问题
- 漏打卡不催促；连续 3 天未打卡，问一句要不要调整提醒时间
- 满 2 周数据前不下"规律"结论，只说"初步观察"
- "初步观察"阶段的周报只能产生"弱"强度证据

### 输出与完成

- **输出**：打卡记录、每周能量报告、能量类线索
- **完成标准**（作为模块）：满 14 天打卡，且生成 2 份周报

## 5️⃣ 他人反馈

| 项 | 内容 |
|---|---|
| **定位** | 补上自我认知的盲区，对应乔哈里视窗中的"盲区" |
| **V0.5 范围** | ⏸ 用户用普通表单手动发问卷，回复导入后只存储；生成问卷题目和邀请话术可用，汇总解读在 V1 上线 |
| **触发** | 用户主动发起；或画像生成前由主智能体建议 |
| **输入** | 用户档案、当前高置信度线索（用于设计对照题） |
| **预计时长** | 准备 10 分钟 + 等待回复 3–7 天 + 解读 15 分钟 |

### 流程

1. **选人**：引导用户选 5–8 人，覆盖至少 3 种关系（家人、朋友、同事、上级、下属）
2. **生成问卷**（5 道题，5 分钟内可填完）
   - 你觉得 TA 最突出的 3 个优点是什么？能举个例子吗？
   - 什么时候你觉得 TA 状态最好？
   - 遇到什么事，你会第一个想到找 TA？
   - 有什么事你希望 TA 做得不一样？
   - （可选）用 3 个词形容 TA
3. **帮写邀请话术**，提供"匿名"和"实名"两种选项
4. **发送与追踪**：生成链接，显示回复进度，3 天后提醒用户跟进
5. **汇总**（至少 3 份回复才开始）
   - 提取高频主题
   - 与自评线索对比，分为四类：
     - **共识优势**：自己和别人都认可
     - **隐藏优势**：别人看到了，自己没意识到
     - **自我高估**：自己觉得有，别人很少提（**只标记"他人未提及"，不降级、不算反证**）
     - **需要注意**：别人提到的改进建议
6. **解读对话**：先共识优势，再隐藏优势，最后改进建议，并询问用户感受

### 规则

- 匿名回复要模糊化处理，不能透露是谁说的
- 负面反馈换成建设性说法转述，但不歪曲原意
- 解读"自我高估"时要说明"没人提到不代表你没有"，避免让用户觉得被否定
- "隐藏优势"写入证据后，如果该线索还没有用户本人的经历，顺势请用户讲一个例子："你自己有没有哪次印象特别深？"
- 用户看到批评有情绪时，先接住情绪，再一起分析

### 输出与完成

- **输出**：反馈汇总报告、他人反馈类证据（追加到已有线索）、盲点类线索
- **完成标准**：收到 ≥ 3 份回复，并完成解读对话

## 6️⃣ 测评解读

| 项 | 内容 |
|---|---|
| **定位** | 把外部测评结果转成线索，与对话发现交叉验证 |
| **支持的测评** | 大五人格、VIA 性格优势、盖洛普优势识别、MBTI（标注"仅供参考"） |
| **触发** | 用户上传报告（PDF 或截图），或粘贴结果 |
| **输入** | 测评报告文件、已有线索 |

### 流程

1. **识别**：判断测评类型，提取分数或排名
2. **翻译**：用大白话解释各维度含义，避免术语
3. **对照**
   - **吻合**："你的尽责性很高，这和你讲的'把乱麻理清楚'的故事一致"
   - **矛盾**："测评说你外向性偏低，但你讲了好几次牵头活动的经历，你怎么看？"
   - **新发现**：测评中突出、但对话中尚未出现的特质
4. **请用户回应**：哪些觉得准，哪些觉得不像自己
5. **写入**：吻合部分追加为证据；新发现记为新线索（初始置信度为"线索"）
6. **收尾**：本次小结之后，询问是否删除测评原文件，只保留分数；用户的选择会被记住，下次不再问（R7）

### 规则

- 测评只是参考来源之一，权重不高于真实经历
- 测评证据基础权重为 0.5（经历为 1.0），同一种测评做多次只算 1 条
- MBTI 只用于启发对话，不产生证据，不计入置信度
- 不使用"你是 XX 型人"这种说法
- 对照逐条出现，回应当前一条才出现下一条；**每条都可以"先跳过"**，跳过的对照不产生证据，在本次小结中列为"未回应"（R2）

### 输出与完成

- **输出**：测评摘要、测评类证据、新线索、矛盾点清单
- **完成标准**：用户回应了所有矛盾点

## 7️⃣ 画像生成

| 项 | 内容 |
|---|---|
| **定位** | 把证据库整合成一份可追溯依据的个人画像 |
| **触发** | 高置信度线索 ≥ 3 条；用户要求；有新证据后需要更新 |
| **输入** | 全部线索和证据、故事库、价值观 Top 5、能量报告、上一版画像 |

### 流程

1. **筛选与检查**
   - 先做一次全量相似度检查，处理遗漏的合并
   - **统一过目自动合并**：把所有"待过目"的合并列给用户（"这几条我之前合在了一起，你看对吗？"），不同意的立即拆回
   - 标记"待补例子"的线索如果仍只有自述证据，放进"待观察"并注明"你提到过，还缺具体例子"
   - 只有"中"及以上置信度的线索进入正文，"线索"级放入"待观察"，已归档的不出现
2. **组织结构**

   ```
   一、核心优势（3–5 个）：描述 + 证据 + 适合发挥的场景
       └ 习得技能：做得好但消耗大的事，单独标注
   二、别人眼中的你：别人看到、但你自己的经历里还没出现的优势 + 补例子的提示
   三、需要管理的短板（2–3 个）：描述 + 证据 + 建议（补短 / 绕开 / 交给别人）
   四、价值观 Top 5
   五、能量模式：充电来源 / 消耗来源
   六、我的最佳状态说明书：在什么环境、做什么事、跟什么人一起时最好
   七、待观察的线索（含"他人未提及"的注明）
   八、和上一版相比的变化（如有）
   ```

3. **反方审核**：交给独立的审核子智能体检查
   - 是否有结论只有单一来源支撑
   - 是否过度美化或过度贬低
   - 结论之间是否互相矛盾
   - 是否用标签代替了描述
4. **修订**：根据审核意见调整
5. **逐段确认**：带用户逐部分阅读，每部分问"准吗？有没有想改的？"
6. **定稿**：保存为新版本，支持导出

### 规则

- 每条结论都必须能点开看证据
- 措辞匹配置信度："中"用"可能 / 很可能"，"高"和"已验证"用"明显"；反对证据较多（W− ≥ W+ × 0.3）的写成"可能是……，但也有相反的情况"
- 画像保存生成时的线索快照，之后线索变化不影响已定稿的版本
- 短板用中性说法，不用"缺点"一词
- 用户修改的内容要标记，但保留原始证据
- 画像标题下固定一句："这是目前证据最充分的样子，不是定论"，避免一句话标题被理解成定论（R5）
- 能量模式一节可以列出打卡中的观察，但必须标"打卡 · 不计入"，不影响任何线索的置信度（R4）

### 输出与完成

- **输出**：画像（带版本号）、可导出的文档
- **完成标准**：用户确认全部章节，或对修改进行了标记
- **建议下一步**：行为实验

## 8️⃣ 行为实验

| 项 | 内容 |
|---|---|
| **定位** | 在现实中验证画像结论，让认识变成行动 |
| **触发** | 画像生成之后；用户想验证某条线索 |
| **输入** | 画像、中高置信度线索、用户档案（目标） |
| **周期** | 设计 10 分钟 → 执行 1–2 周 → 复盘 10 分钟 |

### 流程

1. **选一条线索**：优先选与用户目标最相关的、或仍有争议的
2. **设计实验**（小、具体、1–2 周内能完成）
   - 假设："如果我真的擅长结构化，那么主动梳理一个混乱的项目时，我会感到投入，并得到正面反馈"
   - 行动：这周在工作中主动认领一次梳理任务
   - 观察指标：执行时投入度（1–10）、做完后的能量、别人的反应
3. **约定复盘时间**，设置提醒
4. **中途关心**：执行期间询问一次进展（不催促）
5. **复盘**：发生了什么、感受如何、结果支持还是推翻假设、有无意外发现
6. **更新**：结论为"支持"时产生一条实验证据（权重 1.2），线索已达"高"则升级为"已验证"；结论为"推翻"时产生一条强反对证据并重新计算

### 规则

- 同时最多进行 2 个实验
- 实验不能涉及重大决定（如辞职）
- 实验"失败"也是收获，要明确告诉用户

### 输出与完成

- **输出**：实验记录、行为实验类证据、线索状态更新
- **完成标准**：完成复盘并更新线索状态

## 9️⃣ 安全守护（横向技能，始终在线）

| 项 | 内容 |
|---|---|
| **定位** | 保护用户，守住"自我探索"和"心理治疗"之间的边界 |
| **运行方式** | 对每一轮用户输入做后台检测，优先级高于所有其他技能 |

### 风险分级与应对

| 等级 | 信号举例 | 应对 |
|---|---|---|
| **低** | 讲到难过的往事、有一些消极情绪 | 正常共情，放慢节奏，问用户要不要先换个话题 |
| **中** | 持续低落、失眠、频繁说"我很没用"、提到长期创伤 | 暂停当前模块，温和建议寻求心理咨询，提供求助渠道 |
| **高** | 提到自伤、轻生，或有人身危险 | 立即中断所有技能，表达关心，给出当地危机干预热线，鼓励马上联系身边的人或专业机构 |

### 规则

- 不做诊断，不说"你有抑郁症"之类的话
- 不扮演治疗师，不进行创伤治疗
- 风险解除前不恢复探索流程
- **中风险期间的对话不产生证据**：暂停期间讲的内容不写入故事和线索，本次发现面板写明这一点（R6）
- **恢复条件**：用户主动表示好些了、想继续，且下一轮没有风险信号，教练确认后恢复；**高风险之后至少隔一天**才恢复；恢复时不直接回到低谷话题，先给用户几个方向选择（R6）
- 中、高风险事件做脱敏记录，用于改进产品
- 低谷模式和他人反馈解读环节，检测更敏感

### 输出

风险等级、处理记录、是否可以恢复流程

## 附：V0.5 实施范围

第一版按"开发成本 × 验证价值"挑选，目标是凑齐 3 种证据来源，让画像能出现"高"置信度结论。

| 组件 | V0.5 状态 | 说明 |
|---|---|---|
| 主智能体 | ✅ 完整 | 成长教练人格 + 路由（能量分析、他人反馈、行为实验的路由暂不启用） |
| 目标设定 | ✅ 完整 | 建立用户档案 |
| 经历挖掘 | ✅ 完整 | 高光 + 低谷 + 日常模式 |
| 价值观澄清 | ✅ 完整 | 第 2 种证据来源 |
| 测评解读 | ✅ 完整 | 第 3 种证据来源 |
| 画像生成 | ✅ 完整 | 先不接反方审核子智能体，用自检清单替代 |
| 安全守护 | ✅ 完整 | 风险分级与转介 |
| 能量分析 | ⏸ 只做打卡 | 每日打卡照常记录；不生成周报、不产生证据 |
| 他人反馈 | ⏸ 只做收集 | 用普通表单手动发问卷，回复导入后只存储；不汇总、不产生证据 |
| 行为实验 | ❌ | V2 |

**为什么能量分析和他人反馈先只收集数据**：这两个模块的验证周期由时间决定（14 天打卡、3–7 天等回复），和开发快慢无关。开发期间先攒数据，V1 上线分析功能时就有现成数据可用。

**路线**
- **V0.5**：以上范围，只给自己用
- **V1**：上线能量分析周报、他人反馈汇总解读；按调参日志调阈值；证据按维度衰减；支持 3–5 个朋友试用
- **V2**：行为实验、反方审核子智能体、定时提醒、问卷自动发送
