## 1. 设计原则

| 原则 | 含义 | 落到数据上 |
|---|---|---|
| **证据先于结论** | 任何结论都必须由证据支撑 | 线索本身不存"结论"，置信度由证据实时计算 |
| **可追溯** | 每条画像结论都能追到原话 | 证据保存来源对象 ID 和原文摘录 |
| **独立性** | 同一件事不能被重复计数 | 证据带"独立性键"，同一个键只算 1 条 |
| **用户主权** | 用户可以确认、修改、否认、删除 | 用户的回应单独存字段，系统判断和用户意见分开记录 |
| **只追加，不覆盖** | 认识的变化本身就是有价值的信息 | 变更写日志；画像按版本保存 |
| **最小化** | 敏感内容只存必要部分 | 原文摘录限长；第三方反馈做匿名化 |

## 2. 实体总览与关系

### 2.1 实体清单

| 分组 | 实体 | 说明 |
|---|---|---|
| **核心** | 线索 `Clue` | 关于用户的一个"假设"，如"擅长把复杂的事结构化" |
| | 证据 `Evidence` | 支持或反对某条线索的一条具体材料 |
| **素材** | 故事 `Story` | 经历挖掘产出的 STAR 故事 |
| | 价值观排序 `ValueRanking` | 价值观澄清产出的 Top 5 |
| | 能量打卡 `EnergyLog` | 每日打卡记录 |
| | 能量周报 `EnergyReport` | 每周分析结果 |
| | 反馈请求 `FeedbackRequest` | 一次他人反馈活动 |
| | 反馈回复 `FeedbackResponse` | 一位反馈人的回答 |
| | 测评结果 `Assessment` | 一次外部测评 |
| | 行为实验 `Experiment` | 一次实验的设计和复盘 |
| **产出** | 画像 `Portrait` | 某一版本的个人画像 |
| **支撑** | 用户档案 `UserProfile` | 目标、困惑、偏好 |
| | 对话进度 `Progress` | 各模块状态 |
| | 安全事件 `SafetyEvent` | 风险识别记录（脱敏） |
| | 变更日志 `ChangeLog` | 所有线索和证据的变更 |

### 2.2 关系图

```
                    UserProfile (1)
                         │
     ┌───────────┬───────┼────────┬────────────┬────────────┐
     ▼           ▼       ▼        ▼            ▼            ▼
   Story   ValueRanking EnergyLog FeedbackReq  Assessment  Experiment
     │           │       │  │        │             │            │
     │           │       │  ▼        ▼             │            │
     │           │       │ EnergyReport FeedbackResp│            │
     │           │       │  │        │             │            │
     └───────────┴───────┴──┴────────┴─────────────┴────────────┘
                         │  （每个素材可产生多条证据）
                         ▼
                    Evidence (N) ──── 指向 ────▶ Clue (1)
                                                 │
                                    Clue ◀──相关/矛盾──▶ Clue
                                                 │
                                                 ▼
                                    Portrait（引用线索快照）
```

**关键关系**
- 一个素材（如一个故事）→ 可以产生多条证据，分别指向不同线索
- 一条证据 → 只指向一条线索
- 一条线索 → 有多条证据（支持或反对）
- 线索之间 → 可以有"相关"或"矛盾"关系
- 画像 → 保存生成时的线索快照，不随线索后续变化而改变

## 3. 核心实体：线索与证据

### 3.1 线索 `Clue`

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `clue_id` | 字符串 | ✅ | 如 `clue_0007` |
| `statement` | 字符串 | ✅ | 系统表述，行为化描述，≤ 30 字。例："擅长把复杂的事结构化" |
| `user_statement` | 字符串 | | 用户修正后的说法（有则画像优先使用） |
| `type` | 枚举 | ✅ | 见 3.3 |
| `dimension` | 枚举 | ✅ | 性格 / 能力 / 价值观 / 能量 / 关系 / 盲点 |
| `keywords` | 字符串数组 | | 用于合并检索，如 ["结构化", "梳理", "规划"] |
| `status` | 枚举 | ✅ | 见第 7 节状态机 |
| `confidence` | 对象 | ✅ | 系统计算，见第 8 节 |
| `user_stance` | 枚举 | ✅ | 未回应 / 认同 / 部分认同 / 否认 |
| `deny_count` | 整数 | ✅ | 用户否认次数，默认 0 |
| `related_clues` | 数组 | | `[{clue_id, relation: 相关/矛盾/包含}]` |
| `scenarios` | 字符串数组 | | 适合发挥或容易触发的场景（优势/短板用） |
| `created_by` | 枚举 | ✅ | 首次产生该线索的技能 |
| `created_at` / `updated_at` | 时间 | ✅ | |

> 💡 **写法要求**：`statement` 用"行为 + 情境"描述，不用标签。✅ "在混乱的局面里，倾向先梳理结构再行动"；❌ "INTJ""完美主义者"。

### 3.2 证据 `Evidence`

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `evidence_id` | 字符串 | ✅ | 如 `ev_0031` |
| `clue_id` | 字符串 | ✅ | 指向的线索 |
| `direction` | 枚举 | ✅ | 支持 / 反对 |
| `source_type` | 枚举 | ✅ | 见 3.4 |
| `source_ref` | 字符串 | ✅ | 来源对象 ID，如 `story_0003`、`fbr_0002` |
| `independence_key` | 字符串 | ✅ | 独立性键，见 8.2 |
| `excerpt` | 字符串 | ✅ | 原话摘录，≤ 100 字 |
| `interpretation` | 字符串 | ✅ | 系统的解读：为什么这条材料支持/反对该线索 |
| `strength` | 枚举 | ✅ | 弱 / 中 / 强（由产生它的技能判断，见 8.3） |
| `user_confirmed` | 布尔 | ✅ | 用户是否认可这条解读 |
| `created_by` | 枚举 | ✅ | 产生证据的技能 |
| `created_at` | 时间 | ✅ | |
| `is_active` | 布尔 | ✅ | 被用户删除或判定无效时置为 false（不物理删除） |

### 3.3 线索类型 `type`

| 类型 | 说明 | 能否进入画像 |
|---|---|---|
| 优势候选 | 做得好 + 有能量 + 愿意持续做 | ✅ 核心优势 |
| 习得技能 | 做得好，但做完消耗大 | ✅ 放在优势旁边单独标注 |
| 短板候选 | 反复吃力或回避的事 | ✅ 需要管理的短板 |
| 价值观 | 看重的东西 | ✅ 价值观 Top 5 |
| 能量来源 | 让人充电的活动或环境 | ✅ 能量模式 |
| 能量消耗 | 让人耗竭的活动或环境 | ✅ 能量模式 |
| 行为模式 | 反复出现的做事方式（中性） | ✅ 最佳状态说明书 |
| 盲点 | 自己没意识到，别人或数据显示出来的 | ✅ 需要管理的短板 / 待观察 |
| 不一致 | "说的"和"做的"不一致 | ❌ 只作为对话中的探讨问题 |

> 新增"习得技能"类型，用来落实"优势 ≠ 擅长的事"这条核心认识。判断依据：能力类证据为支持，但能量类证据为反对。

**一条线索只有一种类型。** 如果一段材料同时指向两种类型，就拆成两条线索，并互相标记 `related_clues: 相关`。

| 例子 | 拆分结果 |
|---|---|
| "自主权对我很重要，被管得太细会消耗我" | ① "自主权对我很重要"（价值观）② "被管得过细会明显消耗我"（能量消耗），两条互相标记"相关" |

- **为什么拆**：两条线索的证据来源往往不同（价值观澄清支持前者，能量打卡支持后者），分开计算置信度更准确，画像中也能各自放进对应章节
- **同一个故事可以同时给两条线索各提供 1 条证据**：独立性键只在同一条线索内部去重，不跨线索
- 与第 10 节"情境依赖要拆成两条"的处理方式一致

### 3.4 证据来源 `source_type`

| 来源 | 产生技能 | 对应素材 | 基础权重 |
|---|---|---|---|
| 经历 | 经历挖掘 | Story | 1.0 |
| 价值观 | 价值观澄清 | ValueRanking | 0.8 |
| 能量 | 能量分析 | EnergyReport | 0.8 |
| 他人反馈 | 他人反馈 | FeedbackResponse | 1.0 |
| 测评 | 测评解读 | Assessment | 0.5 |
| 实验 | 行为实验 | Experiment | 1.2 |
| 用户自述 | 任意技能 | 对话中的直接自我评价（含用户主动新建的线索） | 0.3 |

- **测评权重低于经历**：落实"测评只是参考，权重不高于真实经历"。
- **MBTI 不产生证据**：只能产生"线索"（作为对话素材），权重为 0。
- **用户自述**：如"我挺擅长沟通的"，没有具体事例，只能作为辅助，不能单独让线索升级。
- **用户主动新建线索**：允许。登记为新线索（`created_by = 用户`），附一条"用户自述"证据，AI 当场追问一个具体例子，把自述转成"经历"证据（见 9.3）。
- **实验权重最高**：它是在现实中的主动验证。

## 4. 素材实体

### 4.1 故事 `Story`

| 字段 | 类型 | 说明 |
|---|---|---|
| `story_id` | 字符串 | 如 `story_0003` |
| `mode` | 枚举 | 高光 / 低谷 / 日常 |
| `title` | 字符串 | 一句话标题，如"大学组织 200 人活动" |
| `period` | 字符串 | 大致时间，如"2019 年 大三" |
| `domain` | 枚举 | 学业 / 工作 / 家庭 / 社交 / 兴趣 / 其他 |
| `star` | 对象 | `{situation, task, action, result}`，每项 ≤ 200 字 |
| `key_moment` | 字符串 | 最投入或最难受的环节（关键追问的回答） |
| `feelings` | 字符串数组 | 当时的情绪词 |
| `emotion_intensity` | 整数 1–5 | 情绪强度；低谷 ≥ 4 时通知安全守护 |
| `people` | 字符串数组 | 涉及的角色（只存关系，如"室友""主管"，不存真名） |
| `completeness` | 枚举 | 完整 / 缺 STAR 要素 / 中断 |
| `derived_clues` | 数组 | 产生的证据 ID 列表 |
| `user_can_delete` | 布尔 | 恒为 true |

### 4.2 价值观排序 `ValueRanking`

| 字段 | 说明 |
|---|---|
| `ranking_id` | 如 `vr_0001` |
| `shortlist` | 初选的 10 个价值观 |
| `tradeoffs` | 取舍记录数组：`{选项A, 选项B, 选择, 理由, skipped}`；`理由` 原话即证据的 excerpt，为空时证据强度为"弱"；用户追问 2 次后仍跳过时 `skipped = true`，不产生证据 |
| `top5` | `[{rank, value, user_definition}]` |
| `inconsistencies` | 发现的"说的 vs 做的"不一致 `[{描述, 相关故事ID}]` |
| `confirmed_at` | 用户确认时间 |

> 价值观排序可以有多个版本（用户的价值观会变），画像引用最新确认版本。

### 4.3 能量打卡 `EnergyLog` 与周报 `EnergyReport`

**EnergyLog**

| 字段 | 说明 |
|---|---|
| `log_id`、`date` | 每天最多 1 条 |
| `score` | 1–10 |
| `charge_event` | 最充电的一件事 |
| `drain_event` | 最消耗的一件事 |
| `note` | 可选补充 |
| `tags` | 周分析时系统补充：`{activity_type, with_whom, environment}` |

活动类型枚举：独处 / 协作 / 社交 / 执行 / 创造 / 学习 / 休息

**EnergyReport**

| 字段 | 说明 |
|---|---|
| `report_id`、`week_start` | |
| `log_count` | 本周有效打卡数 |
| `stage` | 初步观察（累计 < 14 天）/ 规律（≥ 14 天） |
| `patterns` | 最多 3 条：`{描述, 支持的打卡ID, 出现次数}` |
| `suggestion` | 1 条建议 |
| `user_feedback` | 用户对周报的回应 |

> 只有 `stage = 规律` 的周报才能产生"中"及以上强度的证据。

> **V0.5 的打卡观察**：画像"能量模式"一节可以引用打卡记录，但只作为展示，标"打卡 · 不计入"，不生成 Evidence，不影响置信度（R4）。

### 4.4 反馈请求 `FeedbackRequest` 与回复 `FeedbackResponse`

**FeedbackRequest**

| 字段 | 说明 |
|---|---|
| `request_id` | 如 `fbq_0001` |
| `mode` | 匿名 / 实名 |
| `questions` | 问卷题目快照 |
| `invitees` | `[{invitee_id, relation, status: 未发/已发/已回}]`（不存联系方式明文） |
| `sent_at`、`reminder_at` | |
| `summary` | 汇总结果：共识优势 / 隐藏优势 / 自我高估 / 需要注意 |

**FeedbackResponse**

| 字段 | 说明 |
|---|---|
| `response_id` | 如 `fbr_0002` |
| `request_id` | |
| `relation` | 家人 / 朋友 / 同事 / 上级 / 下属 / 其他 |
| `answers` | 各题回答 |
| `anonymized_text` | 匿名模式下，去掉可识别细节后的版本（对用户只展示这个） |

### 4.5 测评结果 `Assessment`

| 字段 | 说明 |
|---|---|
| `assessment_id` | |
| `instrument` | 大五人格 / VIA / 盖洛普 / MBTI / 其他 |
| `taken_at` | 测评时间 |
| `raw_file_ref` | 上传文件引用；解析后询问是否删除，删除后为空 |
| `scores` | `[{维度, 分数或排名, 大白话解释}]` |
| `matches` / `conflicts` / `new_findings` | 与已有线索对照的结果；每项带 `response`：准 / 不准 / 解释 / 跳过 |
| `skipped_items` | 用户"先跳过"的对照项，不产生证据，在本次小结列为"未回应" |
| `counts_as_evidence` | MBTI 恒为 false |

### 4.6 行为实验 `Experiment`

| 字段 | 说明 |
|---|---|
| `experiment_id` | |
| `target_clue_id` | 要验证的线索 |
| `hypothesis` | 如果……那么…… |
| `action` | 具体行动 |
| `metrics` | 观察指标数组 |
| `start_date` / `review_date` | |
| `status` | 设计中 / 进行中 / 待复盘 / 已完成 / 已放弃 |
| `review` | `{发生了什么, 指标结果, 感受, 意外发现}` |
| `verdict` | 支持 / 部分支持 / 推翻 / 无法判断 |

**约束**：同一用户 `status = 进行中` 的实验 ≤ 2 个。

## 5. 产出实体：画像 `Portrait`

| 字段 | 说明 |
|---|---|
| `portrait_id`、`version` | 版本号从 1 递增 |
| `generated_at` | |
| `trigger` | 证据达标 / 用户要求 / 新证据更新 |
| `clue_snapshot` | 生成时所有入选线索的快照（statement、置信度、证据 ID 列表） |
| `sections` | 八个章节内容（见下方结构），每条结论带 `clue_id` 引用 |
| `review_notes` | 反方审核意见及处理结果 |
| `user_edits` | `[{章节, 原文, 修改后, 原因}]` |
| `section_confirmations` | 每个章节的确认状态 |
| `diff_from_previous` | 新增 / 升级 / 降级 / 移除的线索 |
| `status` | 草稿 / 审核中 / 待确认 / 已定稿 |

**画像入选规则**

| 置信度 | 处理 |
|---|---|
| 已验证、高 | 进入正文，措辞"明显" |
| 中 | 进入正文，措辞"可能 / 很可能" |
| 线索 | 进入"待观察" |
| 已归档 | 不出现 |
| 优势候选，但没有本人经历证据 | 进入"别人眼中的你"，并提示"可以补一个你自己的例子" |
| `not_mentioned_by_others = true` | 等级照常；在"待观察"或对应章节旁注明"反馈里暂时没人提到" |

**画像章节结构**

```
一、核心优势（附习得技能）
二、别人眼中的你：别人看到、但你自己的经历里还没出现的优势（对应乔哈里视窗"盲区"）
三、需要管理的短板
四、价值观 Top 5
五、能量模式
六、我的最佳状态说明书
七、待观察的线索
八、和上一版相比的变化
```

## 6. 支撑实体

### 6.1 用户档案 `UserProfile`

| 字段 | 说明 |
|---|---|
| `user_id`、`nickname` | |
| `goal` | 探索目标（职业方向 / 理解情绪行为 / 改善关系 / 单纯好奇 / 其他） |
| `current_puzzle` | 当前困惑 |
| `life_stage` | 学生 / 职场新人 / 职场中期 / 转型期 / 其他 |
| `comm_style` | `{directness: 直接/温和, examples: 要/不要}` |
| `privacy` | `{allow_training: 默认 false, retention: 永久/1年/会话结束删除}` |
| `goal_history` | 目标变更记录 |

### 6.2 对话进度 `Progress`

| 字段 | 说明 |
|---|---|
| `modules` | `{模块名: {status, started_at, completed_at}}` |
| `counters` | 高光故事数、低谷故事数、打卡天数、反馈回复数等（供路由判断） |
| `last_session` | `{date, skill, summary, open_thread}`：回访开场用 |
| `paused_by_safety` | 是否因安全守护暂停；为 true 期间，所有技能不写入 Story、Clue、Evidence |
| `resume_not_before` | 高风险事件后最早可恢复探索的时间（事件时间 + 1 天） |

### 6.3 安全事件 `SafetyEvent`

| 字段 | 说明 |
|---|---|

## 7. 线索状态机

```
          新建（1 条证据）
               │
               ▼
        ┌──── 待观察 ◀─────────────┐
        │      │                    │ 降级
        │      │ 满足"中"条件         │
        │      ▼                    │
        │    成立中 ────────────────┤
        │      │                    │
        │      │ 满足"高"条件         │
        │      ▼                    │
        │    已成立 ────────────────┘
        │      │
        │      │ 实验结果支持
        │      ▼
        │    已验证
        │
        │ 用户否认 2 次 / 反证占优 / 被合并
        ▼
      已归档 ──（用户要求恢复）──▶ 待观察
```

| 状态 | 对应置信度 | 说明 |
|---|---|---|
| 待观察 | 线索 | 刚出现，证据不足 |
| 成立中 | 中 | 有初步支撑 |
| 已成立 | 高 | 多来源支撑 |
| 已验证 | 已验证 | 经实验检验 |
| 已归档 | — | 不再参与画像，但保留记录 |

> 状态由置信度计算结果自动决定，不能手动直接改；用户的认同或否认通过影响计算来改变状态。唯一的例外是"已归档 → 待观察"的恢复操作。

## 8. 置信度计算规则

### 8.1 计算步骤

每次线索的证据或用户回应发生变化，都重新计算一次：

```
第 1 步：取有效证据（is_active = true）
第 2 步：按 independence_key 去重，同一键只保留强度最高的一条
第 3 步：分别统计支持和反对证据
         有效支持数 N      = 去重后支持证据的数量（不含"用户自述"）
         来源种类数 S      = 支持证据涉及的 source_type 种类（不含"用户自述"）
         加权支持分 W+     = Σ（基础权重 × 强度系数）
         加权反对分 W−     = 同上，针对反对证据
第 4 步：按下表判定等级
第 5 步：应用用户回应和反证修正（8.4）
```

**强度系数**：弱 = 0.5，中 = 1.0，强 = 1.5

### 8.2 独立性键 `independence_key`

| 来源 | 键的生成方式 | 效果 |
|---|---|---|
| 经历 | `story:{story_id}` | 同一个故事拆出多条证据，只算 1 条 |
| 价值观 | `values:{ranking_id}` | 同一次价值观澄清只算 1 条 |
| 能量 | `energy:{report_id}` | 每份周报算 1 条 |
| 他人反馈 | `feedback:{response_id}` | **每位反馈人算 1 条**（5 个人说同一点 = 5 条） |
| 测评 | `assess:{instrument}` | 同一种测评做多次只算 1 条 |
| 实验 | `exp:{experiment_id}` | 每次实验算 1 条 |
| 用户自述 | `self:{clue_id}` | 无论说几次都只算 1 条 |

### 8.3 证据强度判定（由产生证据的技能打分）

| 强度 | 判断标准 |
|---|---|
| **强** | 有具体行为细节 + 结果 + 明确的情绪或能量信号；或多位反馈人独立提到 |
| **中** | 有具体事例，但细节或结果不完整 |
| **弱** | 间接关联、需要较多推断；或只有一句概括；**两难题只选不说理由**（R1） |

### 8.4 等级判定表

| 等级 | 条件（同时满足） |
|---|---|
| **已验证** | 达到"高" + 至少 1 条实验证据，且 `verdict = 支持` |
| **高** | N ≥ 3，S ≥ 2，W+ ≥ 3.0，且 W− < W+ × 0.3 |
| **中** | （N ≥ 2 且 W+ ≥ 1.5）或（N ≥ 1 且 `user_stance = 认同` 且该证据强度 ≥ 中） |
| **线索** | 其余情况 |

**优势类线索的额外门槛（本人经历证据）**

- 适用于 `type = 优势候选` 的线索
- 要达到"高"或"已验证"，支持证据中**至少要有 1 条本人经历证据**（来源为"经历"或"实验"）
- 不满足时：等级**最高封顶为"中"**，标记 `needs_example = true`，画像中放进"别人眼中的你"一节，而不是"核心优势"
- **为什么**：优势 = 做得好 + 做完有能量 + 愿意持续做。别人只能看到"做得好"，后两点只有用户自己能回答
- 用户补上一个具体经历后，重新计算，满足条件即可升级

> 和《技能规格说明书》原规则相比，增加了加权分和反证比例两道门槛，避免"3 条弱证据"或"支持和反对差不多"的线索被写成核心结论。

### 8.5 用户回应与反证修正

| 情况 | 处理 |
|---|---|
| 用户认同 | 可触发"中"的第二种条件，不直接升到"高" |
| 用户部分认同 | 记录 `user_statement`，置信度不变 |
| 用户否认（第 1 次） | 等级降一级；对话中追问更准确的说法 |
| 用户否认（第 2 次） | 状态改为"已归档" |
| W− ≥ W+ × 0.3 | 最高只能到"中"，画像中写成"可能是……，但也有相反的情况" |
| W− ≥ W+ | 降为"线索"，并创建一条"不一致"或新的替代线索供探讨 |
| 实验 `verdict = 推翻` | 产生一条强反对证据，再重新计算 |
| **他人反馈中没人提到**（自评有、他人未提） | **不算反证，不影响置信度**；标记 `not_mentioned_by_others = true`，在反馈解读中归为"自我高估"，画像"待观察"中注明"反馈里暂时没人提到，可以继续留意" |

> **"没有证据"不等于"有反证"**：反馈问卷只问"最突出的 3 个优点"，没被提到可能只是排得不够靠前，或反馈人没机会看到这一面。只有反馈人**明确说出相反的情况**（如"他其实挺急躁的"），才算反对证据。

### 8.6 计算示例

线索"擅长把复杂的事结构化"：

| 证据 | 来源 | 独立性键 | 强度 | 加权分 |
|---|---|---|---|---|
| 大学活动最投入前期梳理 | 经历 | story:0003 | 强 | 1.0 × 1.5 = 1.5 |
| 同一故事里"写了流程表" | 经历 | story:0003 | 中 | （去重，不计） |
| 同事：乱的时候找你准没错 | 他人反馈 | feedback:fbr_0002 | 中 | 1.0 × 1.0 = 1.0 |
| 大五人格·尽责性 高 | 测评 | assess:大五 | 中 | 0.5 × 1.0 = 0.5 |
| 朋友：你做计划很有条理 | 他人反馈 | feedback:fbr_0004 | 中 | 1.0 × 1.0 = 1.0 |

N = 4，S = 3，W+ = 4.0，W− = 0 → **高（已成立）**

## 9. 线索合并与去重

新线索产生时，先检查是否已有相似线索，避免同一特质被拆成多条。

### 9.1 判断流程

```
新线索候选
   │
   ├─ 与已有线索比对（同 dimension 内，按语义 + keywords）
   │
   ├─ 高度相似（同一件事的不同说法）
   │     → 不新建，作为证据追加到已有线索
   │     → 告诉用户"这已经是第 N 次出现了"
   │
   ├─ 部分相似（一个是另一个的具体表现）
   │     → 新建，并添加 related_clues: 包含
   │     → 例：“擅长写会议纪要” 包含于 “擅长把复杂的事结构化”
   │
   ├─ 方向相反
   │     → 作为反对证据追加到已有线索，或建立“矛盾”关系
   │
   └─ 不相似 → 新建线索
```

### 9.2 规则

- **系统只能建议合并，不能静默合并已被用户确认过的线索**；合并前要向用户复述一次
- 合并时保留两条线索的全部证据，`statement` 优先用用户认可过的那一条
- 合并、拆分都写入变更日志，可以撤销
- **未确认的线索由 AI 自动合并**，不打断对话，但记录为"待过目"（`merge_review = 待过目`）
- 画像生成前，执行一次全量相似度检查，并把所有"待过目"的自动合并**统一列给用户过目一次**；用户不同意的合并立即撤销（拆回原线索）

### 9.3 用户主动新建线索

```
用户："我觉得我很有耐心"
   │
   ├─ 1. 先走合并检查（9.1），相似则追加为自述证据，不新建
   ├─ 2. 否则新建线索：status = 待观察，附 1 条"用户自述"证据（权重 0.3）
   ├─ 3. AI 当场追问："能讲一次你特别有耐心的经历吗？"
   │      ├─ 用户讲了 → 转入经历挖掘（日常或高光模式），产生"经历"证据
   │      └─ 用户暂时想不起 → 不强求，标记"待补例子"，之后的对话中留意
   └─ 4. 线索仍按第 8 节计算，自述证据不能单独让它升级
```

## 10. 矛盾与反证处理

| 矛盾类型 | 例子 | 处理方式 |
|---|---|---|
| **来源之间矛盾** | 测评说外向性低，但多个故事都在牵头活动 | 在测评解读或画像中作为探讨问题提出，不自动判定谁对 |
| **说的与做的矛盾** | 说看重成长，但高光故事都和被认可有关 | 创建"不一致"类型线索，只在对话中探讨 |
| **情境依赖** | 在熟人中外向，在陌生人中内向 | 建议拆成两条带情境的线索，而不是互相抵消 |
| **随时间变化** | 三年前讨厌公开演讲，现在喜欢 | V0.5：证据不衰减，标注证据时间，较新的证据在画像措辞中优先；V1：按维度衰减（见第 15 节） |

> 原则：**矛盾本身就是有价值的发现**。画像里可以出现"你在 A 情境下……，在 B 情境下……"，这比一个平均化的结论更真实。

## 12. 隐私与数据安全

| 数据 | 敏感度 | 措施 |
|---|---|---|
| 故事、打卡原文 | 高 | 加密存储；用户可单条删除；删除故事时，其产生的证据一并失效并重新计算置信度 |
| 他人反馈 | 高（涉及第三方） | 匿名模式只向用户展示匿名化文本；不存反馈人联系方式明文 |
| 测评原文件 | 中 | 解析后询问是否删除原文件，只保留分数；选择记入 `UserProfile.privacy.keep_raw_assessment`，下次不再问（R7） |
| 安全事件 | 高 | 只存信号类别，不存原话；中、高风险暂停期间的对话内容不转为证据（R6） |
| 画像 | 中 | 导出和分享需用户主动操作；教练模式需逐次授权 |

**用户权利**
- 一键导出全部数据（JSON + 可读文档）
- 一键删除全部数据
- 默认不用于模型训练
- 可以随时查看"系统记住了我什么"

## 15. 已决问题与后续计划

| 问题 | 结论 | 状态 |
|---|---|---|
| **置信度阈值是否需要调** | V0.5 先用本文档第 8 节的数值；每次用户觉得某条结论"不像我"或"早该成立了"，记录到调参日志（线索 ID、当时等级、用户意见），V1 根据记录调整 | ⏳ 用一段时间后再看 |
| **证据是否随时间衰减** | **V0.5 不衰减**，只在画像措辞中优先新证据。**V1 升级为按维度衰减**：性格、价值观维度不衰减；能力、能量、行为模式、关系、盲点维度的证据，超过 3 年权重减半（具体年限 V1 再定） | ✅ 已决 |
| **线索合并由谁判断** | **分情况 + 画像前统一过目**：未确认的线索由 AI 自动合并；已确认的线索合并前必须先问用户；画像生成前把所有自动合并统一列给用户过目一次，不同意即撤销（见 9.2） | ✅ 已决 |
| **用户能否直接新建线索** | **可以，并且马上追问例子**：登记为线索 + 自述证据（权重 0.3），AI 当场请用户讲一个具体例子，把"我觉得"转成"我做过"（见 9.3） | ✅ 已决 |
| **一条线索能否有多种类型** | **不能，拆成两条并标记相关**：一段材料同时指向两种类型时，拆成两条线索分别计算置信度（见 3.3） | ✅ 已决 |
| **只有他人看到的优势能否到"高"** | **不能**：优势类线索要到"高"，至少需要 1 条本人经历证据（经历或实验）；否则封顶"中"，画像中放进新增的"别人眼中的你"一节，并提示补例子（见 8.4） | ✅ 已决 |
| **他人未提及是否影响置信度** | **不影响**：没人提到不算反证，只标记"他人未提及"，在反馈解读和"待观察"中注明；只有明确的相反描述才算反对证据（见 8.5） | ✅ 已决 |
